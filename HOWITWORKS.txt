STICKERS PROJECT — HOW IT ALL WORKS
====================================

WHAT IT IS
A password-gated sticker board at https://stickers.ozzyabc.xyz. Users enter a
password, see a grid of PNG stickers for that password's board, and can upload
new stickers by tapping a circular contenteditable element and sending an iOS
sticker from their keyboard. Clicking a grid sticker opens a "save as sticker?"
modal so people can long-press and save it on iOS. Upload only, no deletion.

HOSTING CHAIN (server: ozzy@100.76.152.46, Debian 12)
1. cloudflared tunnel (/etc/cloudflared/config.yml) maps
   stickers.ozzyabc.xyz -> http://localhost:8093
2. Caddy (/etc/caddy/Caddyfile) has a ":8093" block:
   - root * /var/www/stickers (static files)
   - reverse_proxy /api/* localhost:3002
3. Node backend (no npm dependencies) runs as systemd service
   stickers-backend.service, listening on 127.0.0.1:3002.
IMPORTANT: the Caddyfile and cloudflared config are AUTO-GENERATED by
/home/ozzy/sync-projects-user.py from projects.json in the portfolio repo
(ozzyDev27/Portfolio). The stickers entry is the last item in projects.json
(ports are assigned by list position: 8081 + index, so stickers = 8093 —
do not reorder that file). The sync script has a hardcoded special case for
stickers in build_caddy_text() that emits the reverse_proxy /api/* line.
Manual edits to the Caddyfile/cloudflared config get overwritten on sync.

FILE LOCATIONS ON SERVER
- Repo clone: /home/ozzy/sites/stickers/ — static files (index.html,
  style.css, app.js, noise.png) live at repo root and are deployed to
  /var/www/stickers/ by /home/ozzy/sync-projects-user.py (which git-pulls every
  repo listed in the portfolio repo's projects.json and copies repo contents,
  minus .git/node_modules/.github/__pycache__, into /var/www/<name>).
  NOTE: server/ and HOWITWORKS.txt also get copied to /var/www/stickers, so
  server.js is technically downloadable — it contains no secrets.
- Backend: /home/ozzy/sites/stickers/server/server.js
- Service unit: /etc/systemd/system/stickers-backend.service
  (User=ozzy, ExecStart=/usr/bin/node /home/ozzy/sites/stickers/server/server.js,
  Environment=STICKERS_DB_PATH=/home/ozzy/db/stickers, Restart=always)
- Data: /home/ozzy/db/stickers/<password>/*.png
  Each subdirectory of /home/ozzy/db/stickers IS a valid password. There is no
  password list file anywhere; the backend just checks whether the folder
  exists. To add a new board: mkdir /home/ozzy/db/stickers/<newpassword>
  Currently existing board: stickersyippee

BACKEND API (server.js)
- POST /api/enter          body {"password": "..."} -> 200 {ok:true} or 403
- GET  /api/list?pw=X      -> {stickers:[filenames]} newest first (filenames
                              start with Date.now() so reverse lexicographic
                              sort = newest first)
- POST /api/upload?pw=X    raw PNG bytes as body -> {file: name}. Validates the
                              PNG magic bytes, 10MB max (MAX_BYTES const).
                              Saves as <timestamp>-<4 random hex bytes>.png
- GET  /api/img/<pw>/<file> -> the PNG, immutable cache headers
Password validation: 1-64 chars, [a-zA-Z0-9_-] only (prevents path traversal),
then folder existence check. Wrong password always returns 403 the same way.

FRONTEND (site/)
- index.html: gate screen (#gate) + board screen (#board) + modal (#viewer).
- app.js: on gate submit, calls /api/enter; success swaps screens (password
  kept only in a JS variable, NOT persisted — users re-enter every visit by
  design). The circle is a contenteditable div; iOS stickers arrive either via
  the paste event (clipboardData image items) or as <img> nodes inserted into
  the contenteditable (caught by a MutationObserver which fetches the img src
  as a blob). Either path goes through toPngBlob() which redraws on a canvas to
  normalize to PNG, then POSTs to /api/upload. New uploads are prepended to the
  grid client-side; full grid order comes from /api/list on load.
- style.css: pastel lavender/peach gradient, background-position + hue-rotate
  animation over 30s (keyframes "drift"), disabled under
  prefers-reduced-motion. Grain overlay is a fixed div tiling noise.png at
  220x220 with opacity 0.14. Font is Baloo 2 (Google Fonts).
- noise.png: 220x220 grayscale random noise, generated by a one-off Python
  script (zlib/struct hand-rolled PNG). Regenerate however you like if lost.

LOCAL DEV COPY
The repo lives at /Users/ozzy/Documents/GitHub/Stickers with static files at
the repo root and the backend in server/. Run locally with:
  STICKERS_DB_PATH=/tmp/stickersdb node server/server.js
plus any static file server for the root (you'd need to proxy /api to :3002 or
just test the API directly, since the frontend uses relative /api paths).

DEPLOYING CHANGES
1. Commit and push to github.com/ozzyDev27/Stickers (main branch).
2. Run the sync on the server (same flow as other projects) — it git-pulls
   ~/sites/stickers and copies to /var/www/stickers.
3. Backend changes additionally need: sudo systemctl restart stickers-backend
(ozzy has passwordless sudo on the box.)
